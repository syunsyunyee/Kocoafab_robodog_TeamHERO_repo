# AIGO 로보독 도우미

PC와 로보독을 연결해 **카페 키오스크 주문 연습**과 **복약 시간 알림**을 제공하는 교육용 프로젝트입니다. 처음 화면에서 두 기능을 선택합니다. 실제 주문·결제는 하지 않습니다.

## 주요 기능

- 키오스크 주문 연습: 음료·온도·크기·옵션·사이드 선택, 16개 단계와 마지막 무작위 미션
- 안내 방식: 가이드 / 스스로 연습, 기본 안내·힌트·자세한 도움의 정보량 구분
- 로보독 반응: 눈 LED·내장 소리·여러 몸동작 조합, 반응을 하나씩 실행
- 복약 알리미: 여러 시각과 약 이름 등록, 약 5초 간격 짖기, 영문 대문자 STOP QR 응답 후 준비 자세 복귀
- 예약 전체 종료: 현재 알림과 등록된 예약 목록 종료·삭제
- 로보독이 없을 때: 모의 모드로 화면과 흐름 확인

## 실행 방법 — Thonny

1. 이 저장소를 `Code → Download ZIP`으로 내려받아 압축을 풉니다.
2. 폴더와 파일 위치를 그대로 유지합니다.
3. Thonny에서 `main.py`를 엽니다.
4. 실행 환경은 **PC의 Python 3**을 사용합니다. MicroPython 보드에 업로드하지 않습니다.
5. F5로 실행하고 `모의 모드` 또는 `실제 로보독 연결`을 선택합니다.
6. `기능 선택 열기 · 브라우저`를 누릅니다. Python이 로컬 서버를 실행하고 브라우저를 엽니다.

모의 모드는 Python 표준 라이브러리와 Tkinter를 사용합니다. Tkinter는 시작 설정 창을 표시하는 데 필요합니다. 실제 로보독을 연결할 때는 제조사가 제공하는 `kocoafab_robodog` 라이브러리를 **Thonny가 사용하는 Python 환경에** 별도로 준비해야 합니다. 제조사 라이브러리는 이 저장소에 포함하지 않았습니다.

실제 연결 시 Windows 장치 관리자의 포트 번호를 확인해 시작 설정 창에 `COM3`과 같이 입력합니다. 코드에서 기본값을 바꾸려면 `main.py`의 `DEFAULT_PORT`를 수정합니다. PC와 로보독만 연결하며 micro:bit 별도 프로그램은 필요하지 않습니다.

## HTML 파일과 Python의 관계

두 기능은 별도의 HTML 두 개가 아니라 **`web/index.html` 하나에 통합**되어 있습니다.

```text
main.py → 연결 설정 창
        → web_kiosk.py의 로컬 Python 서버
        → 브라우저의 web/index.html + app.js + readable.css
        → 주문 처리 / 복약 알림 / 로보독 제어
```

`web/index.html`을 직접 더블클릭하면 Python API가 없어 전체 기능이 작동하지 않습니다. `main.py`로 시작해야 합니다. GitHub에 소스를 업로드하는 것과 인터넷에서 앱을 실행하도록 배포하는 것은 다릅니다. 이 버전은 PC 로컬 실행용이며 GitHub Pages용 정적 데모는 포함하지 않습니다.

## 주요 파일

| 경로 | 역할 |
|---|---|
| `main.py` | Thonny 실행 시작점·연결 설정 |
| `web/index.html` | 키오스크·복약 알림 공통 화면 |
| `web/app.js` | 화면 표시와 Python API 통신 |
| `web/readable.css` | 현재 화면 스타일 |
| `web/styles.css` | 함께 보관한 화면 스타일 파일 |
| `web/assets/` | 음료 이미지·로보독 그림·STOP QR |
| `web_kiosk.py` | 로컬 웹 서버·주문/학습 상태·복약 기능 연결 |
| `medication.py` | 시간·약 이름 예약·반복 알림·QR 응답 |
| `robot_controller.py` | 로보독 연결과 명령 실행 워커 |
| `reactions.py` | 여러 몸동작·표정·소리 조합 |
| `core.py`, `curriculum.py`, `guidance.py` | 주문 규칙·학습 단계·안내 내용 |
| `data/guidance.json` | 기본 안내 문구 |
| `tests/`, `run_tests.py` | 기존 프로젝트 테스트 |
| `check_environment.py` | 실행 환경 확인 |
| `kiosk.py` | 기존 Tkinter 화면 코드·참고 구현 |
| `references/` | 이미지 출처·생성 기록 |

## 로컬 데이터

실행하면 학습 진도·결과와 복약 예약이 `data/`에 생성될 수 있습니다. 업로드 묶음에는 기존 개인 사용 기록이나 복약 예약을 넣지 않았습니다. `.gitignore`는 기본 안내 문구를 제외한 `data/`의 생성 파일을 Git 추적에서 제외합니다. GitHub 웹 업로드는 직접 선택한 파일을 올리므로, 나중에 다시 업로드할 때도 생성된 기록을 선택하지 않습니다.

## 개발 과정과 범위

팀의 서비스 설계와 화면·동작 요구를 바탕으로 개발했으며 코드 작성·수정에 AI의 도움을 활용했습니다. 복약 기능은 기존 코드를 통합한 부분을 포함합니다. 음료 이미지는 생성 모델로 만든 이미지와 기존 참고 이미지가 포함되며 관련 기록은 `references/`에 있습니다. 모의 동작 확인과 실제 하드웨어 반응은 구분해야 합니다.

STOP QR은 사용자의 확인 응답입니다. 실제 약 복용을 판별하거나 처방·용량·약물 상호작용을 판단하는 기능은 없습니다. PC와 Python 프로그램이 켜져 있어야 알림이 동작합니다.

## 수동 업로드

`UPLOAD_GUIDE.md`의 GitHub 웹 업로드 순서를 참고합니다. ZIP 자체를 저장소에 올리는 대신, 압축을 풀고 그 안의 소스 파일과 폴더를 업로드합니다.
